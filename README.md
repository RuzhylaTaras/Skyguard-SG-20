# SkyGuard SG-20

Комплект каталогу даних і контрактів JSON Schema 1.0.0. Основні схеми відповідають критеріям Jira: пакет статусного оновлення та SOS. Додаткові схеми ShelterFeature й AuditEntry виконують деталізацію SG-20 з опису проєкту.

## Файли

- `schemas/status-update.schema.json` – тіло `POST /api/v1/shelters/{shelter_id}/status`.
- `schemas/sos.schema.json` – тіло запропонованого `POST /api/v1/sos`.
- `schemas/shelter-feature.schema.json` – публічна проєкція одного GeoJSON Feature; відповідь каталогу може об’єднувати такі об’єкти у FeatureCollection.
- `schemas/audit-entry.schema.json` – серверний запис журналу; це не дозвіл клієнтам записувати журнал через API.
- `data_dictionary.json` – 78 описів полів для 10 сутностей, класи даних, власники, формати та походження рішень.
- `examples/` – вигадані структурно валідні пакети. Хеш `aaaa…` в прикладі AuditEntry є заглушкою формату; цілісність ланцюга цим прикладом не підтверджується.
- `validate.py` – перевірка JSON із увімкненими форматами UUID і date-time.
- `test_schemas.py`, `validation_report.json` – відтворювані перевірки контрактів і фактичний результат.
- `backend_checks.md` – обов’язкові перевірки, що потребують серверного контексту.

## Запуск

Потрібен Python 3.10 або новіший. Працюйте з кореня розпакованого комплекту.

```bash
python -m pip install -r requirements.txt
python validate.py schemas/status-update.schema.json examples/status-update.valid.json
python validate.py schemas/sos.schema.json examples/sos.valid.json
python test_schemas.py
```

`validate.py` повертає код 0 для валідного пакета, 1 для невідповідності схемі, 2 для помилки читання або синтаксису JSON. `test_schemas.py` повертає ненульовий код, якщо фактичний результат хоча б одного сценарію не збігся з очікуваним.

## Контракт

Використано JSON Schema Draft 2020-12. Усі схеми самодостатні, зовнішніх `$ref` немає. `$id` виду `urn:skyguard:...` є ідентифікатором, а не адресою розгорнутого сервісу. Метасхема діалекту перевіряється бібліотекою `jsonschema`.

Імена полів чутливі до регістру. Доменні поля мають snake_case; `requestId` залишено відповідно до специфікацій SG-6. Схеми об’єктів забороняють неописані поля. Необов’язкове поле пропускається; `null` дозволений лише там, де явно зазначено. Рядки часу використовують UTC із `Z`, секунди та за потреби до шести цифр дробової частини. Перевірку `format` потрібно явно вмикати у валідаторі; звичайного розбору JSON недостатньо.

Шаблон shelter_id `SH-<код>-<номер>`, обмеження довжин, UUID, назви полів SOS і перелік типів інцидентів є профілем SkyGuard, запропонованим у SG-20. Це не твердження про зовнішній стандарт ДСНС. Формат телефону – знак `+` і 8–15 цифр; він не підтверджує існування номера.

У StatusUpdateRequest передаються `consent_id` та GPS, але не роль, ID автора, виміряна відстань або хеш аудиту. Ці відомості визначає сервер. У SOS `shelter_id` і контакт необов’язкові; для `OTHER` потрібен змістовний `message`. Правило радіуса 100 м до SOS не застосовується.

## Метадані та доступ

Власник у каталозі – відповідальний за зміст і якість даних у проєктній моделі; це не юридичне право власності. Коди власників розкрито в `owners`. `origin=source` позначає наявність поля/правила у вихідному описі; `origin=design` – деталізацію контракту. Навіть для джерельних полів конкретні regex, довжини й структура є проєктними обмеженнями SG-20.

Клас усього пакета не нижчий від найвищого класу його полів. StatusUpdateRequest і SOSRequest – SENSITIVE, AuditEntry – CONFIDENTIAL, ShelterFeature – PUBLIC. Публічне поле shelter_id всередині SOS не робить SOS публічним. User, Role та ConsentRecord є серверними сутностями; їхні рядки каталогу не дозволяють клієнту довільно змінювати права або згоду.

StatusReport доповнює прийнятий StatusUpdateRequest серверними полями; SOSRecord аналогічно доповнює SOSRequest. Окремої схеми запису для цих сутностей тут не надається. Сирі GPS, приватні коментарі й контакти не публікуються через карту та загальні WebSocket-події.

95 перевірок стосуються синтаксису й JSON Schema. Запуск живого API, перевірку JWT, реєстру згод, кворуму, Haversine або математичної правильності SHA-256 вони не засвідчують.
