# Перевірки серверного контексту

JSON Schema перевіряє структуру, типи, обов’язковість, enum, числові межі, regex та ввімкнені формати. Успішна перевірка не є дозволом виконати операцію.

1. **Автентифікація та RBAC.** Визначити автора й роль із перевіреного токена. Для захищеної операції без автентифікації – 401, без належного права – 403. Клієнтські actor_id чи role не приймаються у вхідних пакетах.
2. **Згода.** За consent_id перевірити на сервері власника, стан відкликання, версію політики та належну мету обробки. Для статусу – STATUS_GEOFENCE; для SOS – SOS_HANDLING як запропоноване розширення. Сам UUID не є доказом згоди.
3. **Ресурс.** Зіставити shelter_id в тілі та шляху API; перевірити існування укриття й актуальні координати реєстру. Синтаксично коректний ID може посилатися на неіснуючий об’єкт.
4. **DQ-1.** Лише для статусного підтвердження обчислити Haversine за координатами пристрою та довіреними координатами укриття. Продовження при d ≤ 100,0 м; при d > 100,0 м – 422 DATA_QUALITY_RULE_VIOLATION й аудит. Клієнт не може надсилати власне distance_m.
5. **Час і якість GPS.** Порівняти observed_at із серверним часом і політикою допустимої давності/похибки. Формат date-time не перевіряє актуальність. Числові пороги допустимого віку GPS й accuracy потребують налаштування команди; у джерелі вони не задані.
6. **DQ-2.** Відраховувати 30 хв від останнього довіреного підтвердження; після цього індикатор потребує підтвердження. Значення last_confirmed_at=null означає відсутність такого підтвердження. Це не нове значення enum status.
7. **DQ-3.** Для Citizen рахувати три незалежні узгоджені підтвердження за 15 хв. Для Verified Volunteer чи офіційного коменданта одного достатньо. Прийнятий звіт без кворуму залишається pending; повтори одного автора не є незалежними голосами.
8. **Повторні запити.** requestId обробляти в контексті автентифікованого автора й операції; однаковий ключ із тим самим тілом повертає початковий результат, із іншим тілом спричиняє конфлікт. Сам формат UUID не забезпечує ідемпотентності.
9. **Публікація.** Створювати PUBLIC-проєкцію за дозволеним переліком полів. Не серіалізувати в карту весь внутрішній Shelter або вхідний пакет. Не замінювати невідомий ресурс на false; неповні реєстрові дані потребують перевірки.
10. **SOS.** Не вимагати перебування в 100 м від зареєстрованого укриття. Реєструвати звернення пріоритетно; RECEIVED означає лише прийняття сервером. ACCEPTED встановлюється дією оператора. Контакт і точні координати доступні ініціатору й уповноваженому оператору, а не всім підписникам регіону.
11. **Аудит.** event_id, sequence, timestamp, actor_id, role, distance_m і хеші формує сервер. Перераховувати хеш із визначеної канонічної серіалізації та звіряти previous_hash з попереднім записом. JSON Schema перевіряє лише формат 64 hex-символів. Доступ Security Auditor не дає права редагувати журнал.
12. **Зберігання.** Призначити строки за політикою SG-2. У джерелі для звичайної персональної геолокації передбачено 24 години після тривоги, але для SOS є виняток без конкретного строку: не вигадувати число й не видаляти SOS автоматично за звичайним GPS-таймером. Для SOS потрібна окрема затверджена політика строку та підстав зберігання.

Схеми не обчислюють реальну геодистанцію, не читають JWT або базу даних, не доводять існування номера телефону, не встановлюють намір автора при переставлених координатах, які обидві вкладаються у допустимі діапазони.
